## 2. 起 `.133` 七容器

```bash

```

```
systemctl status docker
cd /opt/demo01
docker compose up -d
docker compose ps
```

期望 `demo01-mysql` / `demo01-redis` 为 `healthy`，其余 `Up`；mysql 首次启动要等 40—60 秒。
代码或前端更新过才加 `--build`。**永远不加 `-v`**（会删数据卷）。

开机自启时三个 Spring 服务可能比 MySQL 先起、连不上库而反复重启——等 mysql 变
`healthy` 后再补一句 `docker compose up -d`（或 `docker compose restart business realtime analysis`）。

## 4. 起 `.102` Flink 并提交作业

### 4.1 起集群

```
/opt/flink/flink-1.17.2/bin/start-cluster.sh
```

浏览器能打开 `http://192.168.23.102:8081` 即成功。**集群一重启，jar 与作业全丢，4.2 必须重做。**

### 4.2 提交实时作业（本机 Git Bash，不用登 `.102`）

```bash
cd "D:/作业/sx/demo01"

# ① 上传 jar（前提：已用 -Pcluster 打出集群包）
curl -s -X POST -F "jarfile=@backend/flink-job/target/flink-job-0.1.0.jar" http://192.168.23.102:8081/jars/upload

# ② 取 jar id，形如 "3e037498-...-6da91297178a.jar"
curl -s http://192.168.23.102:8081/jars
```

③ 把 id 填进 `<JAR_ID>` 后提交：

```bash
curl -s -X POST "http://192.168.23.102:8081/jars/<JAR_ID>/run" -H "Content-Type: application/json" -d '{"entryClass":"com.demo01.flink.RealtimeJob","parallelism":1,"programArgs":"--bootstrap 192.168.23.101:9092 --topic behavior-log --group behavior-realtime-flink --checkpoint file:///opt/flink/checkpoints --host 192.168.23.133 --user demo01 --password 123456"}'
```

```bash
curl -s http://192.168.23.102:8081/jobs/overview    # 期望 "state":"RUNNING"
```

⚠️ 提交前肉眼逐个数字符串间的空格——12 个参数少一个就把下一个值当成裸参数，报「未知参数」。
⚠️ 同一 group 只能有一个作业；`jobs/overview` 里有旧作业先 cancel。

### 4.3 离线作业（平时不用起）

一次性批处理，跑完 FINISHED。要重算时把 `entryClass` 换 `com.demo01.flink.OfflineJob`，
参数换 `--input /root/demo01/in --host 192.168.23.133 --user demo01 --password 123456`。

## 7. 停止

| 顺序 | 在哪 | 命令 |
| --- | --- | --- |
| 1 | Windows | `Ctrl+C` 停造数 |
| 2 | `.102` | `/opt/flink/flink-1.17.2/bin/stop-cluster.sh` |
| 3 | `.101` | `cd /opt/kafka` 后 `bin/kafka-server-stop.sh` |
| 4 | `.133` | `cd /opt/demo01` 后 `docker compose stop` |

**直接关虚拟机也行，数据不丢**（命名卷保留，容器 `restart: unless-stopped` 下次自起）。
⚠️ 不要用 `vmrun stop ... soft`——这三台没装 VMware Tools，必定失败；在系统里 `poweroff`。

## 8. 清库重来（只在要重置演示数据时）

```
cd /opt/demo01
docker compose down -v
docker compose up -d
```

等 40—60 秒再访问。所有登录态失效，重新登录即可。

## 9. 故障对照

| 现象 | 多半是 | 处理 |
| --- | --- | --- |
| 首页 502 / 打不开 | 容器没起全 | `docker compose ps`，缺哪个补哪个 |
| 首页 200 但接口全 502 | Spring 容器在重启 | `docker logs demo01-business` |
| 登录 401「登录已过期」 | Redis 被重启或清空 | 重新登录 |
| 大屏实时数字不动 | 作业没起 | `curl -s 192.168.23.102:8081/jobs/overview` |
| 数字涨得慢 / 只有一半 | 同 group 两个消费者 | 只留一个作业 |
| 埋点发了但不涨、死信在涨 | 时钟差 / event_id 非 UUID | 查 `fail_reason`，`TIME_ILLEGAL` → 第 1 节校时 |
| 提交作业报「未知参数」 | programArgs 少了空格 | 逐字对照 4.2 |
| 前端 504 | 后端没起 / nginx 指错 | `docker logs demo01-web` |

## 附：`.101` / `.102` / `.133` 的命令一行一条

这三台是密码登录的终端，粘带换行的多行命令会被折行、换行符进输入流，报莫名其妙的
`SyntaxError`。一行敲完回车再敲下一条。
